The rule about rules

Provenance, not relevance, is what makes a memory binding. The prompt states it twice and the second time as a correction: applicability (branch-relevance) is never a trust label — a workspace member's event can read applicable while carrying no server-trusted provenance. So the orchestrator may cite an event as evidence in a brief's body, and may not hand it the authority of a guardrail. A guardrail qualifies on permanent + effective scope universal + audience: workspace + not archived + the __jerico_trusted_guardrail tag — and that tag throws event_tags_reserved when it arrives through the request path (events/pipeline.ts:360). Neither the user nor the orchestrator can promote its own note into a rule; only the server puts that block into a brief.

Carried from the source rather than glossed: the outer wrapper "is not yet consumed by any worker prompt and therefore is not an authentication boundary today". The scene must not imply security work that is not being done yet.

Why these were one video and not two

Split, each half had a hole. The creation scene made a group and never sent it anything, so the group was a label; the memory scene dispatched to workers that arrived from nowhere, so the dispatch had no subject. Merged, the group is the thing being briefed and the worker is one you watched arrive. Nothing was added to make that work — the two halves were already about the same object.

The scene opens on the wrong project, and that is the product

The sheet does not open on the page you are standing on. loadTabs reads jerico_orch_tabs_<wsId> and restores the tab that was active when it was last closed; the URL's project opens a tab of its own only when none are open at all. So the honest first frame is somewhere else — orca — over jerico's page, and the first thing the scene does is switch.

Switching is not filtering. Each tab is a genuinely separate orchestrator: its own panel, its own runs, its own history, which the component says in its own words on the phone landing — Each project gets its own isolated orchestrator. Agents and instructions never leak between projects. That is why the register does not lose a row when the tile is pressed, it loses a column: tab scope is authoritative. And jerico's column is not empty — the planner group was made before this scene opened, four idle members in it, the way the event log on the page behind already said: this project has a history. What jerico does not have yet is anything running, which is why the tile lights no dot until the next beat starts something.

Three details are the component's and not the film's. The tooltip, because a tile is two letters and the name has to live somewhere — raised by mouseenter and by focus, which is why it belongs in a scene whose vocabulary is focus. The active tile's accent ring and its own colour as a glow, drawn from 0 0 0 2px var(--t-accent), 0 0 13px -1px <tileColor> rather than invented. And the dot on the project you left: projectHasRunning counts panels, not attention, so orca's worker is still working — green for a worker, amber for an orchestrator with nothing under it yet, which is the precedence the component applies and the pair jerico itself shows in turn.

The dispatch cannot go through the group, and the scene says so

The obvious move is bridge_dispatch_to_group, and it is the wrong tool for this beat. It is a PTY broadcast — send a text message or command to every agent in a group — it attaches no guardrails, and it rejects text containing a reserved guardrail provenance marker. What carries the rules is bridge_dispatch_brief, which auto-includes the server-trusted durable guardrails and fails closed if it cannot read them — and that is per panel. So the group says who is together, not who is dispatched at once, and the scene briefs each member. Drawing a group broadcast that carried rules would be showing something the product does not do.

The group is a team before the orchestrator touches it

The user makes the group and puts four workers in it — Claude Code, Codex CLI, Kimi Code, Antigravity, the four CLIs this machine has installed. That is §3.1's diverse models satisfied before the orchestrator has read anything, so when the prose says "four reviewers, disagree in the open" the picture has already made it true and the dispatch beat has nothing left to spawn — only briefs to send, one bridge_dispatch_brief per panel, because the brief is per panel and the group says who is together, not who is dispatched at once. bridge_spawn_worker remains the orchestrator's own tool for when a team is short; this team is not.

Memory is scoped to where you stand

bridge_get_project_memory is not a second store. It is the event log filtered: soft-archived items out, events recorded on a different git branch than your checkout out, and the ones it could not resolve kept but counted in advisory.unresolved. Every event carries branchRef, commitSha and gitDirty, which is what makes that filter possible at all.

What is quoted and what is a worked example

Quoted: the three startup calls and their order, the tool names, the guardrail rule, advisory.unresolved, the event types (decision, discovery, blocker, phase_complete, note, warning — bridge_record_event's own list), the role palette, the branch badge, and the rail — tile geometry, ring, glow, tooltip offset, dot precedence and the localStorage tab restore. A worked example: the transcript's wording, the second project's name orca, the planner group and its pink — a group made earlier, recoloured out of TEAM_PRESET_COLORS, is a state the product holds, not a claim about it — the counts, the row summaries, and yesterday's story. Partly verified since: the ⏺ glyph is not decoration invented for this drawing — output-tap.ts strips it by name as Claude's TUI decoration when hunting sentinels (:1939, :2457), and the completion-push corpus keys a case on it alongside qwen's ✦. The ⏺ Tool(args) over a two-space ⎿ result shape is already how the web console's orchestrator overlay draws orchestrator output, so this sheet follows an existing in-repo drawing rather than inventing a second one. Still not claimed: the wording of the result lines, and whether a live session wraps or spaces them exactly this way.

Why the log, and not the run history

They are different things and the tool says so: events are separate from run history — they persist across runs and are queryable by role/type/tag. A run ends; a decision does not. That is the whole reason this scene can open on yesterday.

The minimize is the real control

The sheet goes down on the ChevronDown in its own header — the control that exists, doing what it does. No new affordance was drawn for the reveal, and none should be: a tour that invents a gesture teaches a gesture the product does not have.

Every way out

The film's discipline, because the failure is the same one — a piece that covers the screen and cannot be dismissed. Skip is present throughout and is never the primary action; Escape ends it; the window dying ends it; a timeout ends it. They do not share a failure: the film learned that the hard way when two of its three "independent" exits turned out to be one, because both crossed the same preload bridge. Nothing here may stand between the user and the app they just opened.

Reduced motion

Not a shorter cut and not a still. It holds each beat where that beat has settled and then plays the tail, where the only thing moving is the wash lifting. Nothing slides, nothing types, and the pointer does not appear at all — a pointer is motion whose entire purpose is to be followed. The film recorded the reasoning when it stopped cutting dead on a held frame: the accommodation removes the motion, not the ending.

The sequence is movable, and moving it changes what it says

Each beat is a segment with its own clock: everything inside it is written against AT.<key>, and the absolute starts are summed from one array. Reordering the sequence is reordering that array — the durations, the score's cues, the pointer's waypoints and the wash all follow, because none of them holds a number of its own. Verified by actually swapping two of them: no errors, the total unchanged, every landmark where the arithmetic said it would be.

Two things that follow from it, and they are not the same thing. Reordering is not free of meaning — put the group before the panel and the header opens with nothing in it, so the beat where a worker sits ungrouped and then joins simply does not happen. And not every order is available: choosing the project has to come first or every beat after it happens in a project nobody chose, a brief cannot cite rules that have not been read yet, and writing back is the last thing that happens. Movable parts, not a free permutation.
